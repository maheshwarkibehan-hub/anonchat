Storage & Identity Disclosure

Privacy & Transparency Manifesto

AnonChat was engineered on a principle of total honesty: we clearly disclose what is recorded, what is ephemeral, and how your anonymity is preserved. Below is an exact accounting of data handling across client and server.

1. 100% Registration-Free Identity Shield

No user accounts, emails, passwords, phone numbers, or social logins exist on AnonChat. When you join matchmaking, you exist strictly as an ephemeral in-memory socket node. We do not track or map your personal identity.

2. Session Archiving & Storage Transparency

To uphold community safety, quality review, and dataset training, text messages, send timestamps, sender turn order, reply quote references, and message type metadata (such as text, voice_note, or image) are recorded into private session archive files on the server.

  • Server transcripts are strictly restricted to the server administrator and are never exposed across anonymous peer browser sessions.
  • There is no public user database or identity linkage.

3. Ephemeral Media in RAM (Zero Disk Media Storage)

Raw voice note audio recordings and attached image bytes are ephemeral in active server RAM only during room transmission. Neither raw voice audio bytes nor uploaded photo files are saved or retained in server session archive files.

4. Minimal Telemetry & Zero Third-Party Trackers

Your IP address is used strictly by the network stack to maintain the live WebSocket connection. AnonChat contains zero advertising SDKs, zero Google Analytics, zero Meta Pixels, and zero marketing tracking cookies. Browser storage is used exclusively for local UI preferences (such as audio chime mute state).

5. Disappearing Features & Honest Boundaries

We provide client-side ephemeral messaging modes with clear boundaries:

  • 5s Self-Destruct Messages: The message bubble visually dissolves and is removed from both active screens after 5 seconds, though text is included in the server session archive transcript.
  • View-Once Photos: The recipient can view the photo for up to 8 seconds before it is removed from the view. The image bytes are not archived on the server. (Note: view-once cannot prevent external captures such as physical cameras or OS-level screenshots).
